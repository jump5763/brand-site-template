检查日期：2026-10-21。基于实际生产构建、standalone 启动和 Playwright 浏览器请求。

## 五项结果

| 原问题 | 整改后证据 |
| --- | --- |
| 单站编译混入另一模板 | a1 的客户端模板模块只属于 a；b1 只属于 b。准备目录不含未选模板源码或路由。 |
| A 直接加载 B 私有客户端模块 | 全量应用中四商家的首页和菜单页共 8 次资源记录，跨模板私有模块数均为 0。使用当前 client-reference-manifest 的模块 ID 与实际下载 chunk 交叉检查。 |
| CSS 全量扫描 | A 实际加载 CSS 不含 B 的 fade-up；A、B 分别使用自己的样式入口和扫描配置。 |
| standalone 带其他商家数据和 Schema | 单站包的文件、追踪清单及编译后正文均未发现其他商家配置；无另一模板 Schema。 |
| 历史构建缓存递归 | 三种部署包的历史构建路径、.next/cache、外部/断裂依赖链接均为 0。临时工作目录已删除，standalone 仍可独立启动。 |

## 验证命令与证据

- `corepack pnpm test`：6 项行为测试通过，包括同模板商家隔离和干净构建输入。
- `corepack pnpm schema:check`、`corepack pnpm typecheck`、`corepack pnpm lint`：通过。
- `corepack pnpm build --site a1`、`--site b1`、`--all`：生产构建通过。四商家数据均在全量构建中预生成。
- 独立启动 a1、b1 部署包后，所选商家 200，同模板另一商家 404；全量服务四商家的首页和菜单均为 200。
- `node scripts/inspect-build.mjs <a1|b1|all>`：检查产物与追踪，完整结果在 `output/audit/`。
- `output/playwright/<商家>-home.txt`、`<商家>-menu.txt`：浏览器实际请求记录。
- 当时的浏览器请求与模块归属检查结果保留在 `output/audit/browser.json`；专用离线浏览器审计入口现已移除，后续直接进行浏览器验收。

原模板未提供 favicon，浏览器仍可能记录该地址的 404；远程图片与地图可能出现网络或预加载警告。本次未改变这些模板资源。未发现跨模板加载或站内导航错误。

以上检查不代表单站构建可以热合并到全量 Next.js 进程。构建产物仍按完整应用部署。
